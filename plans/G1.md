# G1: Read-only browser

**Goal:** a Graft you can use every day instead of `git log --graph`: open, clone, init or scan repositories, browse each one's graph with commit details and diffs, compare branches, read the reflog, and find anything with Search Everywhere. Nothing in G1 changes a repository's history; the only writes are `init`, `clone`, Graft's own app files, `$GIT_COMMON_DIR/graft/state.json`, and the identity step of onboarding.

**Source notes** (`docs/design/`):
- `03 - Project/01 - Roadmap.md` (G1 row)
- `02 - Features/01 - Commit Graph.md`, `17 - Repositories and Workspaces.md`, `21 - Compare Branches.md`, `16 - Reflog and Recovery.md` (view only), `22 - Onboarding.md` (steps 1, 2, 9, 10)
- `01 - Foundations/02 - Architecture.md` (modules, layers, repository session, refresh, storage locations), `03 - Git Engine.md`, `05 - Accessibility.md` (graph semantics and keyboard), `06 - UI Design.md`, `07 - Threat Model.md` (T13, config writing), `08 - Settings Reference.md`, `09 - Glossary.md`
- `04 - Development/02 - Conventions.md`, `03 - Testing Strategy.md`, `06 - Storage Formats.md`, `07 - Libraries.md`, `08 - Platform Integration.md` (file watching, single instance)
- `05 - Design/01 - Screen Inventory.md` (S1–S8, S37–S40), `02 - Keyboard Shortcuts.md`, `03 - UX Writing.md`
- ADR-1, 2, 3, 4, 7, 19, 22, 23, 24, 25

**Milestone done when:**
- [ ] The author uses Graft daily instead of `git log --graph` (Roadmap).
- [ ] Every G1 screen (S1–S8, S37–S40) handles the Screen Inventory states (loading, empty, error with code and Show output, busy), works by keyboard alone, and has light and dark screenshot tests.
- [ ] The graph meets the Commit Graph targets in the real screen, not the spike: 10k commits laid out in < 300 ms; 500k commits with first screen < 1 s, 60 fps scrolling, < 400 MB (measured as in G0 Task 8, on an idle machine with the window in front).
- [ ] Screen readers read each graph row (Accessibility, "Graph").
- [ ] The G0 spike, its `benchmark` package and the temporary `:app:desktop -> :module:feature:graph` edge are gone.
- [ ] `./gradlew check` passes locally and in CI on all three OSes and `git-min`.

Built bottom to top (ADR-24): core → data → **review** → use cases and app state → UI foundation → features → navigation and app. Stop for review after every task, and for the author's review of the whole data layer after Task 7.

## Task 1: App folders and versioned files

**Modules:** `:module:core:configuration`, `:module:core:preference`

- `AppFolders`: the app data, config, cache and log folders per OS (Architecture, "Storage locations"), `profiles/<id>/` and `backups/`; created on first use (`ensure`). Tests read a fake environment, never the real home.
- `VersionedJsonFile`: the Storage Formats rules for Graft's JSON files: `"version"` first, unknown fields ignored, a newer version read-only and never rewritten, a corrupt file moved to `<name>.corrupt-<time>` with defaults used, atomic writes (temp file, `fsync`, rename) that re-check the version first. Older versions are refused untouched until the migration runner exists.
- `WindowPlacement`: saved window bounds clamped to the screens that exist now (Platform Integration 3.6), applied by `:app:desktop` in Task 20.
- The **contents** (`settings.json` v1, recent and pinned repositories, window state) are models, so they live in `:module:data:app` and are built in Task 7 on these files.

**Tests:** each Storage Formats rule on a real temp file (round-trip, unknown fields, newer version, corrupt variants, older version, an interrupted write, a leftover temp file, parallel writes, unwritable folder), the folders per OS from a fake environment, window clamping.

**Done when:** tests pass; no test writes outside its temp folder.

## Task 2: File watcher

**Module:** `:module:core:watcher` (D9), used only by `:app:desktop`.

- `FileWatcher` interface; implementation on `io.methvin:directory-watcher` (FSEvents on macOS) with Graft's ignore rules (`.git/objects`, ignored build folders).
- Events coalesced into `RefsChanged`, `StatusChanged` (debounced 300 ms), `OperationChanged`; overflow or wake → `FullRefresh`; inotify limit → polling with a status message (Platform Integration 3.1).
- Library added to the catalog per the Libraries note.

**Tests:** real temp folders on all three OSes in CI: create, modify, delete, rename; debounce; overflow forced through a small queue; refs vs status classification.

**Done when:** the event tests pass in CI on macOS, Windows and Ubuntu.

## Task 3: Opening, cloning and initializing repositories (data)

**Module:** `:module:data:git` (`api/models`, `api/repositories`, `implementation/source/local`), `:module:core:git` (one new error kind)

- `RepositoryRepository` (name to settle in review): resolve a folder to its root and common dir (`rev-parse --show-toplevel --git-common-dir`, `-z` where available), detect "not a repository" and **dubious ownership** (`safe.directory`) as their own `GitException` kinds (`GIT-R-OPEN-NF`, a new `…-OWN` type in the code registry).
- Summary for the Home screen and tabs: branch, detached HEAD, dirty, ahead/behind (`status --porcelain=v2 --branch -z`, header and a dirty check only).
- `init` (default branch name) and `clone` (URL, folder, depth, single branch, recurse submodules, `--filter=blob:none`) with progress parsed from `--progress` stderr into a `Flow`. Clone runs with Graft's environment (askpass refuses; system credential helpers still work).

**Tests:** recorded fixtures for porcelain v2 headers (detached, unborn, upstream gone); integration tests in `GitSandbox` for subfolder → root, a symlinked path, a non-repository, a dubious-ownership repository (owner mismatch simulated with `safe.directory` config on the sandbox), clone from a local bare repository with progress, init.

**Done when:** tests pass on the latest Git and on 2.38.

## Task 4: Commit details and diffs (data)

**Module:** `:module:data:git`

- Commit details: full message, author and committer with dates, parents, trailers, signature status (`%G?`), and changed files with status, renames and line counts (`diff-tree -z --raw --numstat -M`).
- Diffs: unified patch for a commit, between two commits, and `A...B`; parsed into files → hunks → lines, with binary, rename, mode-change, and non-UTF-8 handling (GitText). Context and rename settings from `settings.json`.
- File contents at a revision through one long-lived `cat-file --batch` per session (side-by-side view, full messages), cancellable.

**Tests:** fixtures recorded from real repositories (renames, binary, mode change, no newline at end, non-UTF-8 path and content, submodule change, a 10k-line file); a parser benchmark on a large diff.

**Done when:** tests pass; the large-diff benchmark is recorded in the ledger.

## Task 5: Search, filters and compare (data)

**Module:** `:module:data:git`

- Log queries: by message, author, file path (`-- <path>`), content (`-S` / `-G`), and a first-parent option; streamed like the main log.
- Author type for the graph filter: the `Co-authored-by` trailer and bot authors (`[bot]` names) carried as a small flag on `CommitRow` (not the whole trailer, for memory).
- Compare: `A..B` and `B..A` logs, `merge-base`, ahead/behind (`rev-list --left-right --count A...B`), `diff --numstat A...B` and `A B`, and `merge-tree --write-tree --name-only` conflict preview (Git ≥ 2.38).

**Tests:** fixtures and sandbox repositories for each query; the merge-tree preview with a real conflict; `CommitRow` memory checked against the G0 heap figure (no more than 10% growth at 500k rows).

**Done when:** tests pass on both Git versions.

```

│ ⓘ Loading the graph is slow here: this repository has no commit-graph file.                 │
│   Git can write one to speed it up.        [Speed up the graph]  [Not now]                 │
├─ header (TableHeader: right-click hides columns, drag edges to resize) ──────────────────────┤
│ BRANCH / TAG          GRAPH    MESSAGE                                AUTHOR       DATE    SHA │
├──────────────────────────────────────────────────────────────────────────────────────────────┤
│                       ◎        Uncommitted changes (4 files)                                    │  WIP row
│ ✓⑂ main ⇄ origin/main ●        Fix login timeout                      DR Dwiki R.  2 h ago a1b2c3d │  selected: highlight
│                       ●─╮      Merge feature/login                    AL Ann Lee   5 h ago 9f8e7d6 │
│ ⑂ feature/login       │ ●      Add retry                    (match)   🤖 bot       1 d ago 4c5d6e7 │  search match: bold

│ …                                                                                              │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

- **Branch / Tag** shows up to two `RefChip`s, then `+3` (its tooltip and the screen-reader label list them all). The checked-out branch comes first. A local branch and its upstream at the same commit merge into one chip.
- **Graph** is `GraphCanvas`. The column is as wide as the widest row so far, up to `MAX_DRAWN_LANES`.
- **Author** shows `AuthorInitials` and the name, with the bot icon for `AuthorType.BOT`. AI-assisted commits get the AI icon after the message.
- **Date** is relative under a week, then the OS date format, with the exact time in a tooltip (UX Writing). **SHA** shows 7 characters.
- **WIP row:** shown only while `RepoSnapshot.summary.dirty`, on HEAD's lane with the ring marker, saying "Uncommitted changes ({count} files)". It's read-only in G1; Enter on it does nothing yet (the changes panel is G2).
- **Filters:**
  - **Branches menu:** All branches, Current branch (`LogScope.Only(HEAD)`), or the left panel's solo selection, shown as "{n} selected" when one exists.
  - **Hide remotes:** adds every `refs/remotes/*` to the hidden refs.
  - **First parent:** `git log --first-parent`.
  - **Authors:** People, AI-assisted and Bots, as checkboxes. This filter dims the other rows rather than removing them (the author's 2026-11-16 ruling).
  - The filters are saved per repository in `state.json`.
- **Search:**
  - A hash prefix matches at once, through `GraphMatch`. Anything else runs `SearchGraphUseCase`; the field's menu picks message, author, path or content.
  - Matches are bold and everything else is dimmed.
  - Enter and Shift+Enter (or ↑ and ↓ beside the field) go to the next and previous match. The count reads "3 of 12".
  - Esc clears the search and returns focus to the table.

**States**

| State | Shows |
|---|---|
| Loading | Header and graph bar; 12 skeleton rows (blank lane, gray bars) after 300 ms, then real rows as the first batch arrives. "Loading history… 12,000 commits" in the status line under the table while it streams |
| Empty repository | "This repository has no commits yet." centered, and nothing else: committing comes with G2 |
| Git error | The rows already loaded stay. A banner above the rows has the message (UX Writing pattern), the error code, **Retry** and **Show output** (git's stderr and exit code in a dialog). With no rows, it's centered |
| Filtered to nothing | When the branch filter leaves no commits: "No commits on the selected branches." **Show all branches**. When search or the author filter matches nothing, the graph stays and the bar shows "No matches" in the error color |
| Busy | While the commit-graph file is written, the banner shows "Writing the commit-graph file…" with its button disabled, and the graph reloads when it's done |

**Keyboard path** (Accessibility, "Graph"; Keyboard Shortcuts, "Graph")

Tab order: Branches menu → Hide remotes → First parent → Authors → Search field → table. Within the table:

| Keys | Does |
|---|---|
| ↑ / ↓, PageUp / PageDown, Home / End | Moves the selection, scrolling it into view |
| Alt+↓ / Alt+↑ | First parent / first child (the nearest row above whose parents include this commit) |
| Alt+→ | Cycles through a merge's other parents |
| `[` / `]` | Previous / next row that has a ref |
| Enter | Opens commit details (the right panel, Task 14; until then it sends `OpenCommit` to the host) |
| Mod+C | Copies the full hash |
| Mod+F | Focuses the search field |
| Mod+Alt+Home | Jumps to HEAD |
| typing | Speed search over the visible rows' messages and refs; it moves the selection (`SpeedSearchMode.JUMP`), Esc clears |

- Each row is one node, with the lanes hidden. Example: "Commit a1b2c3d, Fix login timeout, by Dwiki Riyadi, 2 hours ago, branches main and origin/main, merge of 2 parents".   - Error: the message, its code, Retry and Show output.
