**Goal:** an empty but correctly shaped Gradle project with CI on three OSes, the `GitRunner` foundation, and a throwaway graph spike that proves Compose Desktop can draw a 500k-commit graph fast enough. The spike either confirms ADR-1 or reopens it before G1.

**Milestone done when:**

- [ ] CI fails on a forbidden module edge, on a Material import outside `ui-kit`, and on a missing SPDX header.

## Task 1: Gradle skeleton

**Files:** `settings.gradle.kts`, `build.gradle.kts`, `gradle/libs.versions.toml`, `gradle/wrapper/*`, `build-logic/` (convention plugins), one folder per module.

- Gradle wrapper (latest stable); Kotlin JVM toolchain 21; Compose Multiplatform plugin (desktop target only).
- Convention plugins in `build-logic/`:
  - `graft.kotlin-library` for `core-*`, `provider-*`, `app-cli`;
  - `graft.compose-library` for `ui-kit`, `feature-*`;
  - `graft.compose-app` for `app-desktop`;
  - Spotless + ktlint applied by all three.
- Modules, all empty except a placeholder file, and dependencies exactly as the Architecture graph draws them:
  - core: `core-model`, `core-git`, `core-repo`, `core-provider`, `core-network`, `core-data`;
  - providers and UI: `provider-github`, `ui-kit`;
  - features: `feature-graph`, `feature-workingcopy`, `feature-shelves`, `feature-worktrees`, `feature-submodules`, `feature-changerequests`, `feature-issues`;
  - apps: `app-desktop`, `app-cli`.
- `app-desktop` opens an empty window titled "Graft".

**Done when:** `./gradlew build` passes; `./gradlew :app-desktop:run` shows the window.

## Task 2: Build checks

**Files:** `build-logic/src/.../checks/*`, `config/module-graph.txt`

- **Module graph check:** `config/module-graph.txt` lists the allowed edges, copied from the Architecture diagram. A `checkModuleGraph` task fails on any project dependency not listed.
- **Import rule:** fails when any source file outside `ui-kit` imports `androidx.compose.material3`, or when any file in `core-*` or `app-cli` imports `androidx.compose`.
- **License header:** fails when a `.kt` / `.kts` file lacks the SPDX header (AGENTS.md §6).
- All three are wired into `check`.

**Tests:** each check has a test fixture that must fail (a bad edge, a bad import, a missing header) and one that must pass.

**Done when:** `./gradlew check` passes, and each deliberate violation makes it fail with a clear message.

## Task 4: CI

**Files:** `.github/workflows/ci.yml`

- Matrix: `macos-latest`, `windows-latest`, `ubuntu-latest`; JDK 21; Gradle cache.
- Steps: `./gradlew check`.
- Git versions: on Ubuntu, a second job runs the `core-git` integration tests against Git **2.38** (built from source or from a pinned container) as well as the runner's latest Git.

**Done when:** the workflow file is valid (`actionlint` if available). It only runs once the repo is pushed, and pushing waits for the user, so CI is reported as "not yet run" until then.

## Task 5: `GitRunner`

**Module:** `core-git` (and `GraftError` in `core-model`)

- `GitRunner.run(command, cwd, input?) : Result<T>` and `stream(command, cwd) : Flow<T>`, per the Git Engine note.
- Process environment: `LC_ALL=C`, `GIT_TERMINAL_PROMPT=0`, `-c core.quotepath=false`, `-c color.ui=never`, `GIT_OPTIONAL_LOCKS=0` for read commands. Askpass and editor helpers are stubs for now.
- argv only, never a shell; a cancellation kills the whole process tree; stderr and the exit code are kept.
- `GraftError` sealed type with `MODULE-LAYER-FUNCTION-TYPE` codes; a git failure maps to `GIT-E-<FN>-<TYPE>`.
- `GitVersion` check: parse `git --version`, require ≥ 2.38.
- A per-repository write queue (ADR-3): mutating commands are serialized and reads aren't.

**Tests** (sandboxed per AGENTS.md §4): run in a temp repo; streaming; cancellation stops the process; a non-zero exit becomes the right error code; old-version detection with a fake `git` script; two parallel writes are serialized.

**Done when:** tests pass on all three OSes locally available (macOS now; Windows and Linux via CI later).

## Task 6: Log and refs parsers

**Module:** `core-git`, models in `core-model`

- `LogCommand`: streams `git log --topo-order -z --format=%H%x00%P%x00%an%x00%ae%x00%at%x00%cn%x00%ct%x00%s` into `CommitRow` (hash, parents, author index, time, subject). Compact storage, per the graph note.
- `RefsCommand`: `git for-each-ref` over heads, remotes, tags, stash and `refs/graft`, into `Ref`.

**Tests:** fixtures recorded from generated repos: merges, an octopus merge, several roots, non-UTF-8 author and subject, an empty subject, annotated vs lightweight tags.

**Done when:** parser tests pass; parsing 500k rows from a recorded stream stays under the budget noted in the plan review.

## Task 7: Graph layout

**Module:** `core-repo` (pure Kotlin, no UI)

- The incremental lane algorithm from the Commit Graph note: `lanes[]` of awaited hashes; the first parent keeps the lane; other parents reuse a waiting lane or take a free one.
- Output per row: the commit's lane, plus the segments entering and leaving each lane.
- Lane colors are stable per branch.

**Tests:** linear history; branch and merge; criss-cross merge; octopus; several roots; a long-running branch; golden-file tests of the row layout. A JMH or simple benchmark: lay out 500k synthetic commits.

**Done when:** tests pass; benchmark result recorded.

## Task 8: Graph spike (throwaway UI)

**Module:** `app-desktop` (spike code under `spike/`, deleted or rewritten in G1)

- Window with a virtualized `LazyColumn`: fixed 24 px rows, one `Canvas` per row drawing lanes and dots, and a subject column.
- Rows stream in from `LogCommand` → layout while scrolling is already possible.
- Test repository: a 500k+ commit history, e.g. a treeless clone (`--filter=tree:0`) of a large public repo like the Linux kernel, outside this repo. Ask the user where to clone it, and get their OK for the download size.
- Measure and record in `progress.md`:

  | Metric | Target (Commit Graph note) |
  |---|---|
  | Time to first screen | < 1 s |
  | Scrolling (fling through 100k rows) | 60 fps, no frame > 32 ms |
  | Memory (heap after full load) | < 400 MB |

**Done when:** measurements are recorded with how they were taken. The user decides: ADR-1 confirmed → G1, or reopened.
