# G2: Working copy

**Goal:** make commits only in Graft. See the working tree's status, stage and unstage by file, hunk or line, discard with a way back, commit and amend, undo the last commit or amend from an operation log, never lose uncommitted work (Local History), work in named groups instead of the index (Changelists), be stopped before a secret or a huge file goes into history (Commit Guards), and ignore and clean safely. G2 is the first milestone that **writes to a repository**, so every write goes through the one-at-a-time write queue (ADR-3), is recorded in the op log, and has a way back (ADR-6).

## Task 1: Temporary index and git write helpers

**Module:** `:module:core:git`

- `TempIndex`: a scoped temporary `GIT_INDEX_FILE` in `.git/graft/tmp/`, created next to the repository (same filesystem), removed on completion or failure, never the user's index (Git Engine). Commands that build trees from it: `read-tree`, `update-index`, `write-tree`, `commit-tree`.
- `git apply` classification: patch rejected, context mismatch and whitespace errors become distinct `GIT-R-APPLY-…` errors with stderr kept.
- Per-command environment (`GIT_INDEX_FILE`, author and committer for snapshots) passed through `GitRunnerConfig`'s sandbox-safe map.

**Tests:** a real repository in `GitSandbox`: a temp index leaves `.git/index` byte-identical; failure and cancellation clean up; apply errors map to their codes.

**Done when:** tests pass on the latest Git and on 2.38.

## Task 2: Working tree status (data)

**Module:** `:module:data:git`

- `WorkingTreeRepository`: `git status --porcelain=v2 --branch -z --untracked-files=all` parsed into `ChangeEntry` (path, original path for renames and copies, index status, worktree status, mode changes, submodule state, unmerged stages) with staged and unstaged views; ignored files on request (`--ignored`); a `Flow` that refreshes on the session's status events.
- Unmerged entries are listed and marked conflicted (resolving them is G3).
- A submodule is one entry with its state from the `S<c><m><u>` flags: pointer moved, modified content, untracked content. Its inner files are not listed in G2 (Submodules, "Review in the parent"; G5).

**Tests:** fixtures recorded from real repositories: renames in the index and worktree, copies, deletes, type changes, non-UTF-8 paths, paths with spaces and newlines, submodules, unmerged states, a large status (50k entries) benchmark.

**Done when:** tests pass on both Git versions; the benchmark is recorded in the ledger.

## Task 3: Selections and patches (data)

**Module:** `:module:data:git`

- `ChangeSelection` / `FileSelection` (`WholeFile | Hunks(ids) | Lines(ranges)`, Working Copy "Selection model"): one type for commit, discard, snapshot restore and, later, stash and shelve.
- `PatchBuilder` (pure): a file's parsed diff plus a selection becomes a patch that applies alone: partial hunks recounted, `\ No newline at end of file` kept, CRLF endings kept, renames, mode changes and binary files handled; a reverse patch for unstage and discard.
- Operations on the write queue: `stage`, `unstage` (`git apply --cached` and `-R`, `git add -N`/`restore --staged` for whole files), `discard` (reverse patch on the worktree, `git clean`-free; untracked files by delete), each preceded by a Local History snapshot when it removes content (Task 4's codec; discard waits on it, see Task 4).

**Tests:** property-style tests: for random selections of a generated diff, staging then `git diff --cached` equals the expected patch, and unstaging everything returns the index to HEAD; fixtures for CRLF files, no-newline, a deleted file, a new file, a rename with edits, a binary file, a mode change, and a file with 10k hunks.

**Done when:** tests pass on both Git versions.

## Task 4: Snapshots and Local History (data)

**Module:** `:module:data:git`

- The snapshot codec: a commit of the whole working tree (tracked plus untracked, ignored excluded, files over the size limit skipped) built with a temp index, parented on the previous snapshot, under `refs/graft/history/<worktree-id>`, with the `Graft-History-Version: 1` trailer and a fixed Graft identity (Storage Formats 3). Deduplicated by tree.
- `LocalHistoryRepository`: take a snapshot (with an optional label), list snapshots with their changed files, a file's versions, files deleted since a snapshot, search by path and by text across snapshots, restore a file, a hunk or the whole tree (the whole-tree restore takes a snapshot first), purge a file from history (T16).
- Retention (every snapshot under 24 h, hourly to 7 days, daily to 30, labelled ones kept), the 10 MB file limit and the 1 GB budget; thinning rewrites the chain.
- `discard` from Task 3 now takes its "before discard" snapshot here (E2).

**Tests:** real repositories: dedupe, chain order, ignored and large files skipped, untracked files captured, the user's index untouched, restore of a deleted file and of a hunk, thinning keeps labelled snapshots, the budget drops the oldest unlabelled, the history ref is never pushed by `git push`, a removed worktree's history.

**Done when:** tests pass on both Git versions; a snapshot of a 100k-file tree is timed and recorded in the ledger.

## Task 5: Operation log and undo (data)

**Modules:** `:module:data:git`, `:module:core:git`

- `OpLogRepository`: append, list and trim the per-repository JSON Lines file (E1), written under the repository's write queue; an entry carries time, worktree, argv (secrets redacted by the runner's existing rules), exit code, a stderr tail, and the refs before and after (HEAD, the current branch, `refs/stash`).
- `MutationRecorder`: wraps a mutating `GitCommand` so the refs before and after are read around it and the entry is written even when the command fails or is cancelled.
- `Undo` / `Redo` for commit and amend (E8): restore the branch to its "before" with `update-ref` and the expected old value, refusing (with an explanation) when the branch moved since.

**Tests:** entries for success, failure and cancellation; trimming at the cap; a corrupt line skipped, not fatal; undo after a restart; undo refused after an outside commit; no argv or stderr ever contains a token.

**Done when:** tests pass on both Git versions.

## Task 6: Commit and amend (data)

**Module:** `:module:data:git`

- Commit of the index or of a selection: summary and description, a 50/72 guide as data (the UI shows it), sign-off, the repository's `commit.template`, signing as git config says (`commit.gpgsign` passes through; Graft never handles keys), `--no-verify` only when the caller says so, co-author trailers (E6).
- Amend (message only, or with staged changes), with the previous message offered.
- Hooks run as normal and their output streams into the op log entry and the Git log.
- Every commit goes through `MutationRecorder` (Task 5).

**Tests:** commit, amend, sign-off and co-author trailers, a template, an empty commit refused, a failing pre-commit hook (nothing committed, output kept), `--no-verify`, signing configured but no key (the error keeps git's stderr), the op log entry and undo for each.

**Done when:** tests pass on both Git versions.

## Task 7: Changelists (data)

**Modules:** `:module:data:app`, `:module:data:git`

- `changelists.json` v1 in `$GIT_DIR/graft/` (per worktree; `VersionedJsonFile`): lists with name, description, commit draft, the active list, and assignments by file or hunk. Hunks are identified by their content and surrounding lines and re-anchored when the file changes; one that can't be re-anchored moves to the active list with a notice (Changelists, edge cases). Assignments follow renames.
- The mode (Inherit / Staging area / Changelists) in the repository's `state.json` (ADR-27's file), and the switch rules: staged changes become a "Staged" list; going back asks whether to stage the active list.
- Commit a list: temp index = HEAD plus the list's hunks, `git commit` with that index, the list's draft as the message; a failing hook leaves the list unchanged.
- Discard a list: the snapshot first (E2).

**Tests:** re-anchoring through edits above, inside and around a hunk, a rename, a deleted file, a branch switch; mode switches both ways; committing a list leaves other lists' changes in the working tree; a hook failure.

**Done when:** tests pass on both Git versions.

## Task 8: Commit guards (data)

**Module:** `:module:data:git` (`guard` package, E5)

- The five checks of the Commit Guards note as pure rules over diff text: secrets (known formats, private key headers, entropy near `password`/`secret`/`token`), sensitive file names, large files (warn over 10 MB, block over 100 MB), conflict markers, case collisions. Findings carry file, line, rule and a **masked** excerpt (`ghp_****…a91F`); the real value is never in a model that reaches the UI or a log (T12).
- Scan sources: the staged diff, a changelist's diff, and a range (used by push in G3), streamed.
- Allow-lists: `guard-allow.json` (fingerprints) and `.graft/guard.toml` (path patterns), read and written with the versioned file helpers; "allow once" is recorded in the op log.

**Tests:** each rule with positive and negative samples (generated fake tokens only, none real), masking, a binary file, a 10k-line diff benchmark, fingerprint stability across line moves, the allow-lists, case collisions on a real repository.

**Done when:** tests pass; the benchmark is recorded in the ledger.

## Task 9: Ignore and clean (data)

**Module:** `:module:data:git`

- Ignore targets: the repository `.gitignore` (root or nearest), `.git/info/exclude`, and the global excludes (`core.excludesFile`, created if missing; the config write goes through the config-writing rules of the Threat Model). Patterns for a file, an extension, a folder, or free text with a live preview (`ls-files --others --ignored --exclude-from=…`).
- `check-ignore -v` for "Why is this ignored?"; `git rm --cached` for an already tracked file; the `.gitignore` templates from `github/gitignore`, bundled (CC0, licence text with the app), merged without duplicate lines.
- Clean: preview with `clean -n -d` (and `-x` / `-X`), sizes largest first, nested repositories and submodules excluded unless explicit, a snapshot first (untracked, non-ignored files only), then `clean -f -- <selected paths>`.

**Tests:** each target and pattern; negation patterns and the warning when a parent folder is ignored; a tracked file; a global excludes file that doesn't exist; clean previews with ignored and nested repositories; the snapshot taken before clean; paths with spaces and leading dashes (T3).

**Done when:** tests pass on both Git versions.

## Task 17: Markdown preview

**Modules:** `:module:core:ui`, `:module:data:git` (only if the revision read is missing), `:module:feature:workingcopy`, `:module:feature:graph`

Source: `02 - Features/33 - Markdown Preview.md`; Threat Model T5; Settings Reference ("Remote images in Markdown").

- `MarkdownView` in `:module:core:ui`: a Graft interface over `multiplatform-markdown-renderer` and JetBrains' `markdown` parser (added to `gradle/libs.versions.toml`, Apache-2.0). CommonMark and GFM, front matter as a collapsed block, code fences through the existing `Highlighter`, raw HTML shown as plain text, task lists read-only, diagram and math fences as code and text. Links: same-file anchors scroll, repository links ask the host to open that file at the same revision, external links show their real target and ask once. Relative images come from the same revision through a loader the host passes in; URL images load only when the setting is on (default off); no network otherwise.
- `MarkdownChanges`: a pure function from two Markdown texts to rendered blocks marked added, removed or changed (blocks matched by kind and content, then words inside a changed block with `java-diff-utils`), so a reflowed paragraph with the same words is unchanged.
- The Diff / Preview / Changes segmented control in `DiffViewer`'s header for `.md`, `.markdown` and `.mdx` files (new or deleted files: Preview and Diff only; over 1 MB it asks first; invalid UTF-8 not offered). The mode is remembered per repository in `state.json`; Diff is the default; `Mod+Alt+M` cycles; the viewer takes both texts in and gives events out, no git inside.
- Wire it into the Changes panel (working tree and staged versions), commit details, Compare (B's version) and Local History (the snapshot's version). If reading a file at a revision (`git show <rev>:<path>`) is not already a repository call from G1, add it to `:module:data:git` with its test. Task 11's `DiffViewer` change is the base; the renderer is also what G6's PR bodies will use.
- Wireframes in this file first (the toggle, Preview, Changes with an added, a removed and a changed block, the over-1 MB prompt, the external-link prompt), then stop for review.

**Tests:** `MarkdownChanges` unit tests (identical, reflowed paragraph, added and removed blocks, a changed word, tables, code fences, front matter); renderer tests that raw HTML, a script tag and a `javascript:` link render as inert text; the image loader makes no network call with the setting off; view-model tests for the mode memory and the which-modes-are-offered rules; screenshots in light and dark for each mode; a real-repository test that the Preview of a file at an old commit is that commit's text.

**Done when:** tests pass; a Markdown file an agent changed can be read rendered, and with its changes marked, from the Changes panel and from a commit, by keyboard alone.
